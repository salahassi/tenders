# Source-bound qualification reserve

This bundle advances [A05](RELIABILITY_REMAINING_GATES.md),
[ME-14/ME-08](RELIABLE_PROPOSAL_ACCEPTANCE.md) and
[D07](RELIABLE_PROPOSAL_DELIVERY_PLAN.md) with synthetic sources, reviewed expected
meanings, an activation lock and offline integrity/scoring tools. It does not
qualify a model, close the private holdout requirement or authorize provider calls.
No task output or production retrieval result has been generated for this reserve.

The authors knew prior development outcomes. Independent colleagues reviewed the
new source/oracle meanings before outputs; this is **not an independently blind or
private holdout**. All sources are synthetic. Existing provider failures and seven
known G09 retrieval misses remain separate evidence, without revised denominators.

## Retrieval scope

Sixteen bilingual query/source pairs cover telemetry triage, catalogue matching,
engineering drawing digitization, customs classification, electricity forecasting,
accessibility review, pseudonymous matching and archival format conversion. Each
source contains an exact supporting fact plus a qualifier or exclusion.

Each has three prospective evaluation cells:

1. `whole_source`: compact source bytes plus six short distractors; all 16 pools
   fit the existing 24,000-byte context bound, without filler.
2. `bounded_context`: a separately hashed assembly has filler before both fact and
   qualifier. The fixed 3,000-byte test budget changes no product limit or threshold.
3. `preflight_excluded`: compact source excluded before selection; this tests
   reinsertion/false absence claims, not database authorization.

Position seven is input order, not measured algorithm rank. Compact and expanded
sources have distinct hashes/spans. The helper reconstructs bytes only. **None of
these 48 cells has run against the production selector.** Future measurements must
retain all fact/qualifier misses, silent/explicit omissions and claim eligibility.
Partial unverified fragments cannot support company claims. No recall threshold
is invented here, and previous measured misses cannot disappear into this reserve.

## Activation and observations

The committed [activation example](../tests/backend/fixtures/qualification-reserve/activation-lock.example.json)
is a draft with no targets or authorization and zero planned invocations. It fails
scheduling. Future activation must freeze the following before outputs:

- Corpus/retrieval hashes, source commit, qualified adapter/validator digests,
  independent oracle-review reference and separately established execution authority.
- Provider/connection/model/configured-name identities, configuration/capability
  hashes, and acceptable provider-reported model identities declared in advance.
- Per case and target: exact canonical input, full prompt and output-schema hashes
  and actual phase contract version. A static registry prompt label is insufficient.
- Two repetitions, zero automatic retries and exactly `100 × target count` slots.

Observations repeat the adapter/input/prompt/schema/contract pins and resolved
target fields. Missing, different, duplicate or foreign receipts are rejected.
Actual provider-reported identity is separate from the configured route: absent
identity stays unknown and cannot complete qualification; unexpected identity fails.
Catalogue enablement is not availability or identity proof.

Receipts preserve POST counts, post-freeze timestamps, output hash, canonical
validator result/digest and nullable token usage. Missing/unavailable/transport-error/
refused/malformed results cannot pass or reduce the scheduled denominator. A refused
or malformed response is completed transport, not domain-valid or semantically
scored; its diagnostic review remains separate.

Adjudications bind the exact output and oracle hashes, reviewer/method/evidence
provenance, known invariant, matching source spans and concrete relevant output paths.
An inspected parent path is accepted for an omission finding only. This mechanical
tool does not parse private outputs to discover truth, authenticate reviewers or
prove independence. A model cannot establish correctness by returning its own pass.

## Scoring and evidence limits

One critical false acceptance, omission or false rejection fails the exact-reserve
gate. Probe protocol failures are separate and also prevent qualification. Missing,
partial or undetermined judgments never pass; a known defect remains a failure even
when other judgments are absent. All scheduled observations need full adjudication.
Unknown actual model identity prevents overall qualification even if semantic
judgments pass.

Reports retain scheduled/observed/attempted/completed/domain-valid/scored counts per
target/task/language, semantic versus probe counts and per-class attempted/completed/domain-valid/scored
invariant counts. The report binds the activation-lock hash and source/adapter/validator
digests; invariant exposures are not additional provider calls.
Repeat comparison requires complete non-undetermined judgments for both repeats.
Changed output hashes are reported separately from changed semantic verdicts.

Noncritical business thresholds remain **unapproved**. No universal accuracy or
population confidence interval is invented for these nonrandom, translation-linked
cases. Future population sampling/interval methods require pre-outcome agreement.
The offline tooling has no network client or provider-execution operation. From
`backend/`:

```sh
node scripts/qualification/reserve-cli.mjs check
node scripts/qualification/reserve-cli.mjs schedule /private/approved-lock.json
node scripts/qualification/reserve-cli.mjs score /private/approved-lock.json /private/observations.json /private/judgments.json
```

The 71 local tests use explicitly synthetic mechanical receipts/verdicts. They test
integrity, request/identity binding, arithmetic, unavailable/missing behavior,
source/path traces and failure preservation. They do not qualify adapters, model
outputs, retrieval recall, hosted behavior or deployment. See the
[execution receipt](evidence/qualification-reserve-freeze-20261104.json).

Before actual evaluation, qualify task-specific production adapters and real
source/authority contexts, resolve remaining business acceptance decisions, supply
an authorized independent private holdout where required, freeze actual targets and
requests, then use the existing authorized campaign mechanism. Preserve authorized
raw outputs privately and every first failure. Mechanical test passes cannot promote
a model route or erase prior failed qualification.
